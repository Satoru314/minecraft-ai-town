# 設計

## 目的

- AI の住人が、サバイバル（イージー）で生き延びながら街を発展させ続ける
- 「何をもって発展とするか」も AI（戦略役）が決める。人間は「住みやすい街を作る」程度の大まかな方針だけを渡す
- すべてローカルで動かす。Web へのアクセスは調べもののためだけに使う
- 人間はゲーム画面を見なくても、記録ファイル（ログ・状態・日記）から状況を把握できる

## 前提とする環境

| 項目 | 内容 |
|---|---|
| マシン | x86_64 CPU 8〜12 コア、RAM 8GB（昼）〜 20GB（夜）、GPU なし |
| メモリ帯域 | DDR4 デュアルチャネル程度（〜40GB/s）。生成の速さはここで決まる |
| サーバー | Minecraft Java 1.21.4（26.1.x では移動がサーバーに拒否され続けたため）、`online-mode=false`、イージー、`keepInventory` オン |

## 構成

```
┌──────────────────────── この システム ────────────────────────┐
│                                                                │
│  strategist（夜）          decider（常駐）          bot（常駐）  │
│  LLM 30B-A3B 級     ──→   判断サーバー       ←──   Mineflayer   │
│  Web 調べもの        計画   2択/選択/採点      問い  反射プラグイン │
│  日記・計画を書く    メモ   logit を直接読む          行動の実行    │
│        ↑                                              │        │
│        └──────────── 記録（events / state / diary） ←─┘        │
└────────────────────────────────────────────────┬───────────────┘
                                                 │ Minecraft プロトコル
                                           Minecraft サーバー
```

### bot（反射 + 行動）

- Node.js + [Mineflayer](https://github.com/PrismarineJS/mineflayer)
- 反射はコードで即座に処理し、判断モデルには聞かない
  - 戦闘: `mineflayer-pvp`、食事: `mineflayer-auto-eat`、防具: `mineflayer-armor-manager`、移動: `mineflayer-pathfinder`
  - HP が低い・敵が多い → 逃げる。夜 → 家に戻る（家がなければ穴を掘ってこもる）
- 行動は「スキル」の集まりとして実装する（木を切る、鉱石を掘る、作業台を作る、設計図どおりに建てる、畑を耕す…）
- どのスキルを次に使うかは decider に聞く

### decider（判断）

- Jev（TypeSafe AI）と同じ発想。文章を生成せず、選択肢ごとの確率を **1回の forward pass で読む**
- 実装（`src/decider/client.js`）: llama.cpp の `llama-server` に、選択肢へ A, B, C… の記号を付けたプロンプトを送り、`n_predict: 1` / `n_probs: 20` で最初のトークンの確率を受け取って、記号の確率だけを正規化する
  - Qwen3.5 は考える過程（`<think>`）を出すモデルなので、`<think>\n\n</think>` を先に埋めて、すぐ記号を答えさせる
  - SemIf（[TheoLeeCJ/SemIf](https://github.com/TheoLeeCJ/SemIf)）と同じ考え方。依存を増やさないよう、llama-server の API だけで実装した
- モデル: Qwen3.5-4B（Q4_K_M）。`scripts/setup-llm.sh` が llama.cpp のコミットとモデルのチェックサムを固定して用意し、`minecraft-ai-llm` サービスで常駐させる
- 速さ（8コア中6スレッド、DDR4）: 読み込み約 53 トークン/秒。状況説明込みで約350トークン → 初回 6 秒前後、前置きがキャッシュに乗れば数秒
- 判断係が落ちていても bot は止まらない（予備の決め打ちルールで選び、`decision` に `fallback: true` を残す）
- 確率は「表示した選択肢の中での」値で、自信の度合いとしては校正されていない
- 今使っている問い方は choice（次の行動）だけ。yes/no と score は必要になったら足す

### 行動の選び方

1. 石の道具（ツルハシ・剣・斧）がそろうまでは、決め打ちの手順（木 → 板材 → 棒 → 木のツルハシ → 石 → 石の道具）
2. そのあとは毎回、**今できる行動だけ**を選択肢にして判断係に選ばせる
   - 木を切る / 石を掘る / 動物を狩る / 家を建てる（材料があるとき）/ 苗木を植える（苗木があるとき）/ チェストにしまう（家があって持ち物が多いとき）/ 家に戻る（遠いとき）/ 探検
   - 状況として、時刻（夜まであと何分か）、HP・満腹度・食べ物の数、持ち物、街の様子（家の数・苗木・チェスト）、最近の死因、直前3回の行動と成否を渡す
   - 2回続けて失敗した行動は、次の1回は選択肢から外す
3. 目標は `data/plan.json` の `goal`。なければ既定の方針（住みやすい街を作る…）

### 建築

- 設計図は `src/bot/build.js`。今は家（5×5、壁は丸石で高さ3、正面に扉の穴、板材の平らな屋根）だけ
- 建てる場所は、今の家（なければ現在地）の近くで、設計図の大きさ＋周り1マスの地面が平らで、上が空いている場所を探す
- 下の段から、隣に固いブロックがあるところに順に置く。届かない・失敗したものは次の周回でやり直す（最大6周）
- 建てかけは `data/town.json` に残るので、中断しても次に続きから建てる。最初に完成した家の扉の前が「家（home）」になる

### strategist（戦略・夜だけ）

- 文章を生成できる LLM（Qwen3-30B-A3B 級、MoE）を llama.cpp で動かす
- RAM を多く使うので **夜（人間が寝ている間）だけ起動**し、その間 bot は休むか単純作業だけ続ける
- やること
  1. その日の events と state を読む
  2. 必要なら Web で調べる（例: 「村人との交易のしかた」「鉄ゴーレムトラップ」）
  3. **攻略メモ**（knowledge/）と **街の計画**（plan.json: 目標の優先順位、建てたいもの、場所）を更新する
  4. **日記**（diary/YYYY-MM-DD.md）を書く
- decider は翌日、plan.json と攻略メモを前置きに入れて判断する

## 記録

人間が直接見るのではなく、「AI アシスタントに聞く」「コマンドで読む」ための記録。

| ファイル | 形式 | 中身 |
|---|---|---|
| `data/events.jsonl` | 1行1イベントの JSON | 時刻・種類（death / build / mine / craft / fight / decision / chat …）・詳細 |
| `data/state.json` | JSON（随時上書き） | 位置・HP・空腹・持ち物・今の目標・今のスキル・建物リスト・生存日数 |
| `data/plan.json` | JSON | 戦略役が決めた目標と建築計画（今は `goal` だけ読む） |
| `data/town.json` | JSON | 家の場所、建てたもの（建てかけを含む）、植えた苗木の数、チェストの場所 |
| `data/diary/YYYY-MM-DD.md` | Markdown | その日の出来事と、AI 自身の振り返り |
| `data/knowledge/*.md` | Markdown | Web で調べてまとめた攻略メモ |

`events.jsonl` の decision イベントには、問い・選択肢・確率・選んだものを残す。後から判断の質を見直したり、学習データにしたりするため。

## Web アクセスの制限

自律で動く AI が Web を読むので、次の制限をかける。

- アクセスしてよいドメインを許可リストで絞る（初期値: `minecraft.wiki`）
- 読んだページの内容は「データ」として扱い、指示としては扱わない（プロンプトで明示し、ツールも Web 取得と保存以外は与えない）
- このシステムを動かすマシンには、他のシステムの秘密情報（API トークン・SSH 鍵など）を置かない
- ローカルネットワークへは Minecraft サーバー以外に出られないようにする（ファイアウォール）
- Wiki のダンプを手元に置いて完全オフラインにする選択肢も残す

## リソースの目安

| 中身 | RAM | 動く時間 |
|---|---|---|
| bot（Node.js） | 〜1GB | 常時 |
| decider（4B, Q4） | 3〜4GB | 常時 |
| strategist（30B-A3B, Q4） | 約18GB | 夜だけ |

速さの目安（DDR4 デュアルチャネルの CPU）: decider は 1 判断 0.5〜2 秒（キャッシュが効けばもっと速い）、strategist は Wiki 1 ページの読み込みに 40〜80 秒、生成は毎秒 15 トークン前後。
同時に動かす必要があるときは、strategist を gpt-oss-20b 級（約12GB）に下げる。

## 決めたこと

| 項目 | 決定 |
|---|---|
| bot の数 | 1体から始める |
| ワールド | 普通のランダム生成 |
| 難易度 | 最初からイージー |
| 死んだとき | `keepInventory` オン（サーバー側の設定）。死因は events に残して次に活かす |
| 発展の定義 | 戦略役に任せる |
| 人間の関わり方 | 当面は記録を読むだけ。のちに人間のプレイヤーも同じワールドに入る |
